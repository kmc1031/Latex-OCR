# 손글씨 수식 OCR: 단일 통합 실험 계획 v2.1

작성일: 2026-11-05. 상태: DATA_PREPARING / 전체 실험 미완료. 이 문서에 기재된 목표 수량·설정은 새 실행 결과가 아니다.

v2에서는 촬영 문항 240개를 확정한 CAPTURE_SHEET.md / capture_plan.json과, 아래 14~24절의 실행 명세를 추가했다. 촬영 문항은 계획이며 수집 사진이나 실험 결과가 아니다.

사용자의 범위 지시: 앞으로 '실험'은 데이터 준비부터 실제 수식 이미지 입력, 기호 분할, CNN 분류, LSTM 구조 생성, LaTeX 표시, 최종 평가·오류 분석까지 포함하는 하나의 실험을 뜻한다. 내부 처리 단계나 담당 코드가 있어도 각각을 별도 실험 완료로 취급하지 않는다.

## 1. 하나의 연구 질문과 성공 판단

연구 질문: 실제 손글씨 수식 이미지를 연결 성분 분할 → CNN → LSTM으로 처리했을 때, 보고서에 사용할 수 있는 정확한 LaTeX를 얼마나 빠르게 생성하는가?

- 주 결과: 새로 수집한 수식 사진 120장의 전체 수식 일치율.
- 보조 결과: 실제 필기 배치를 유지한 MathWriting 시험 수식의 일치율·토큰 편집 거리.
- 분수 질문: 같은 최종 모델이 같은 내용의 상하/슬래시 표기를 인식할 때 성능이 달라지는가?
- 분할·분류·구조별 수치는 이 전체 실험의 오류 진단으로 사용한다.
- 모델 구조, 데이터 관리, 최종 선택 지표를 하나로 고정한다. 주 실행 시드는 42다.
- 과학적 실험 완료와 도구의 실용성 달성은 구별한다. 낮은 성능도 유효한 결과다. 사진 시험·전체 파이프라인 평가가 없으면 전체 실험 완료가 아니다.

## 2. 입력과 출력 범위

기호 클래스 70종:

- 숫자 0~9: 10종.
- 영문 대문자 A~Z, 소문자 a~z: 52종.
- +, -, =, \times, /, (, ): 7종.
- 소수점 .: 1종.

F=ma, v=v_0+at, x^2, a_1, (a+b)/c와 같은 기본 물리·수학 수식을 다룬다. 한 수식에서 보이는 기호는 최대 16개, 출력은 EOS를 포함하여 최대 64토큰(내용 63토큰 이하)으로 제한한다. 분수·첨자는 각각 한 단계까지 지원하고 중첩 분수·행렬·그리스 문자·근호·특수 함수는 범위 밖으로 명시한다.

CNN의 '-'는 가로획 시각 클래스로 사용한다. 빼기와 분수선의 의미 구분은 위치 관계를 입력받은 LSTM이 담당한다. ^, _, 중괄호는 그림에서 직접 분류하는 기호가 아니라 출력 구조 토큰이다.

사전에 범위를 만족하는 수식만 자료에 포함한다. 예측 결과를 보고 어려운 사례를 시험 집합에서 빼지 않는다. 기호 종류가 부족하다고 0/O나 1/l를 같은 라벨로 합치지 않는다.

## 3. 데이터는 실제 수식 중심으로 준비

| 자료 | 학습 목표 | 검증 목표 | 최종 시험 목표 |
|---|---:|---:|---:|
| MathWriting 실제 수식 | 4,000 | 400 | 400 |
| 보조 합성 수식 | 2,000 | 0 | 0 |
| 직접 작성·촬영한 수식 | 72 | 48 | 120 |

위 수량은 확보 목표다. 전체 원본을 지원 기호·길이·구조로 필터링한 뒤 실제 수량과 제외 사유를 기록한다. 부족분을 같은 이미지의 복제나 합성 이미지로 채워 실제 수식 수라고 보고하지 않는다. 수량 변경이 필요하면 학습 전에 계획 버전과 데이터 목록을 갱신한다.

- MathWriting 전체 원본의 train/valid/test 구분을 유지한다. 저해상도 기존 가공본 대신 획 원본에서 다시 렌더링하여 실제 배치를 보존한다.
- 현재 로컬 가공본에는 70종 토큰 범위만 적용했을 때 실제 수식이 학습 4,664개, 검증 207개, 시험 344개 있다. 길이·깊이 등 최종 필터 전의 점검값이므로 목표 확보 완료로 해석하지 않는다.
- 전체 수식은 normalizedLabel, symbols의 개별 기호는 label을 사용한다.
- MathWriting 기호와 CROHME의 학습 기호는 같은 CNN의 보조 학습에 사용할 수 있다. 모두 출처와 원본 수식 ID를 기록한다.
- 부족한 기호는 추가 작성하여 클래스당 서로 다른 원본 50개 이상을 학습용으로 확보한다. 증강본은 원본 수에 포함하지 않는다.
- CNN 보조 기호와 손글씨 합성에는 정답 획만 남긴 이미지/마스크를 사용한다. 이웃 기호가 들어간 bbox crop을 하나의 독립 기호 원본으로 합성하지 않는다.
- 합성 2,000장은 기본 600, 위첨자 300, 아래첨자 300, 분수 400쌍(800장)으로 구성한다. 폰트와 손글씨 기호 합성을 함께 쓰고 글자 크기·간격·기준선·획 두께·분자/분모 폭·분수선 길이를 다양화한다.
- 합성은 학습 보조 자료다. 검증과 주 시험은 실제 필기 자료로 구성한다.

공식 자료: [MathWriting 공식 저장소](https://github.com/google-research/google-research/tree/master/mathwriting).
일반 MathWriting 수식에는 기호 분할 정답이 없다. symbols.jsonl은 일부 기호와 원본 획을 연결하며, 일반 수식 전체의 완전한 분할 정답으로 간주하지 않는다.

팀원 한 명당 학습 24장, 검증 16장, 시험 40장이다. 수식 내용은 세 용도 사이에서 중복되지 않게 문항표로 먼저 정한다. 같은 분수 내용의 두 표기는 같은 용도에 배치한다. 지원 문자와 1/l, 0/O, x/× 혼동 사례가 문항에 포함되도록 한다.

수집 조건:

- 흰 종이에 검은 펜으로 수식 하나를 작성하고 원본 사진을 보관한다.
- 주 시험은 읽을 수 있는 정상 촬영 조건으로 수집하고, 과도한 흐림·잘림 여부를 예측 전에 검수한다.

- =의 두 획, i/j의 점과 몸체는 각각 하나의 정답 기호로 표시한다. 분수선은 독립 가로획으로 표시한다.
- 시험 사진은 새로 수집하고 이전 테스트·UI 예시로 사용한 이미지는 제외한다.

이 구성은 세 필자의 새 수식에 대한 평가다. 세 필자 모두 학습에도 참여하므로 '처음 보는 필자에 대한 일반화'를 입증한 결과로 표현하지 않는다.

## 5. 하나의 전역 데이터 목록과 중복 검사

모든 이미지·기호는 공통 manifest로 관리한다.

필드: sample_id, expression_id, source, source_sample_id, source_glyph_ids, writer_code(있는 경우), official_split, split, structure_type, notation, image_path, image_hash, latex, tokens, glyphs, annotation_version.

- 같은 원본과 모든 변형본은 같은 집합에 배치한다.
- 같은 수식 내용의 상하/슬래시 쌍도 같은 집합에 배치한다.
- 손글씨 원본 기호 풀을 나눈 뒤 합성한다. 학습 합성에는 학습 풀만 사용한다.
- 수식 내용은 정규화된 구문 트리로 식별한다. 검증·시험 내용과 같은 학습 수식은 학습에서 제외하고 수량을 기록한다.
- MathWriting 시험은 과거 사용한 ink_id 목록과 대조하여 새 시험 후보를 고른다. 확보가 부족하면 재사용분을 별도 진단으로 보고하며 새 독립 시험과 합산하지 않는다.
- 파일·획 원본 해시와 이미지 해시를 검사한다. 근접 중복 후보는 검수한다.
- MathWriting에는 공개 필자 ID가 없으므로 임의의 필자 독립 분할을 만들었다고 주장하지 않는다.
- 실제 문항·필터·데이터 수량·분할을 확정한 뒤 manifest 버전과 해시를 잠근다.

## 6. 추론 시 항상 실행되는 단일 파이프라인

1. 이미지 읽기/방향 보정 → 수식 하나의 ROI 선택 또는 자르기.
2. 흑백 변환 → 배경 밝기 보정 → 이진화. 비율을 유지하고 작은 획을 보존한다.
3. 8방향 연결 성분 → 기하 규칙 병합 → 고립 잡음 제거.
4. 각 그룹에 속한 획만 남긴 기호 이미지를 28×28 안에 비율 유지해 넣고 여백을 추가하여 32×32로 만든다.
5. CNN이 70종 기호 확률을 출력한다.
6. 기호 확률과 위치·크기를 x좌표 순으로 정렬하여 LSTM에 입력한다.
7. LSTM이 LaTeX 토큰을 생성한다.
8. 출력 LaTeX와 렌더링한 수식을 표시하고 복사 기능을 제공한다.

정답 좌표·정답 기호·획 작성 순서·정답 수식 길이를 실제 추론에 제공하지 않는다. 분할 후보가 없거나 처리 한도를 초과하면 실패 결과를 반환하고 최종 정확도 분모에 포함한다.

기하 규칙 초기값:

- H: 점/얇은 가로선을 제외한 성분 높이의 중앙값.
- =: 두 가로획의 겹침 ≥ 짧은 획 너비의 0.8, 너비 비율 ≥0.7, 세로 간격 ≤0.5H, 사이 다른 성분 없음.
- i/j: 작은 점이 몸체 위에 있으며 가로 중심 차이 ≤0.25H, 세로 간격 ≤0.4H. 소수점처럼 기준선 아래쪽 점은 이 규칙으로 병합하지 않는다.
- 분수선: 가로로 긴 획을 독립 기호로 유지한다. 주변 기호를 분수선에 병합하지 않는다.
- 한 조각은 한 그룹에만 소속시킨다. 붙은 서로 다른 기호를 무조건 수직으로 자르지 않는다. 해당 실패는 오류 분석에 포함한다.

전처리·병합 임계값은 검증 자료에서 정하고 본 학습과 최종 시험에서 동일하게 사용한다. 좌표 변환을 기록하며 영상 크기 변경 시 영역 좌표도 같이 변환한다.

## 7. 하나의 CNN–LSTM 모델

CNN:

32×32×1 → Conv(16,3×3,padding=1) → ReLU → MaxPool(2) → Conv(32,3×3,padding=1) → ReLU → MaxPool(2) → Flatten(2048) → Dense(64) → ReLU → Dense(70).

각 기호의 LSTM 입력은 78차원이다.

- 기호 확률 70개.
- 중심 x/W, 중심 y/Himage, 너비/W, 높이/Himage.
- 앞 기호와의 중심 x·y 차이/Hchar.
- 너비/Hchar, 높이/Hchar.

기호는 중심 x, 중심 y 순으로 정렬한다. 위치는 잘라낸 32×32 이미지가 아니라 수식 전체에서 계산한다. 상대 기하값은 [-4,4]로 제한한다.

구조 모델:

78차원 → Linear(64)+ReLU → 양방향 LSTM 인코더(방향별 hidden 128, 1층) → 양방향 최종 h,c 연결(256) → LSTM 디코더(hidden 256, 1층, 토큰 임베딩 64) → 토큰 확률.

기호 사전과 출력 토큰 사전은 구분한다. 출력은 문자/숫자를 한 글자씩, LaTeX 명령을 한 토큰씩 나눈다. \frac, ^, _, {, }, BOS, EOS, PAD, UNK를 포함한다.

슬래시와 상하 분수의 정답은 구문 트리를 통해 같은 \frac 형태로 직렬화한다. 문자열 치환으로 처리하지 않는다. 예: a+b/c → a+\frac{b}{c}, (a+b)/c → \frac{a+b}{c}. 대소문자와 소수점은 보존한다.

## 8. 학습은 전체 모델을 완성하는 한 절차

이 절차 안에서 CNN 초기화·LSTM 적응·공동 미세조정을 진행하고, 최종 산출물은 하나의 통합 체크포인트다.

1. 보조 기호 정답으로 CNN을 10에포크 초기 학습한다. Adam, lr=0.001, batch=64, 교차 엔트로피를 사용한다.
2. 실제 수식에서 자동 분할한 입력으로 LSTM을 학습한다. 첫 3에포크는 CNN을 고정하여 확률 의미를 유지한다.
3. 이후 CNN과 LSTM을 공동 미세조정한다. 이산적인 연결 성분/병합 규칙은 고정한다. 전체 토큰 손실의 기울기가 CNN 확률까지 흐르게 한다.
4. 주 손실은 수식마다 토큰 수로 정규화한 LaTeX 교차 엔트로피의 배치 평균이다. 보조 기호 분류 손실을 0.3 가중치로 더하여 CNN의 기호 의미가 무너지지 않게 한다.

본 학습 설정:

- 수식 배치 10장: MathWriting 실제 6, 합성 3, 촬영 1. 보조 기호 배치 64개를 함께 사용한다.
- 학습 집합 안에서 구조별 과소표집을 점검하고 부족 구조의 추출 확률을 조정한다. 고정한 확률을 설정 파일에 기록한다.
- 실제 수식과 사진을 포함하는 70%의 입력은 실제 필기다. 같은 사진을 다시 뽑은 것을 새 원본으로 세지 않는다.
- CNN lr=0.0001, 인코더/디코더 lr=0.001, Adam, gradient norm≤5.
- 최대 60에포크. 15에포크 이후 검증 선택 점수가 8에포크 연속 개선되지 않으면 종료한다.
- teacher forcing은 학습에서만 사용한다. 검증·시험은 이전 예측을 입력하는 자유 생성으로 수행한다.
- 이미지 증강은 학습에만 적용한다. 약한 회전 ±5°, 비율 유지 크기 변화, 여백·밝기·획 두께·약한 흐림을 사용한다. 반전은 사용하지 않는다.
- 증강한 전체 이미지에서 분할과 기하 계산을 다시 수행한다. 이전 좌표를 그대로 사용하지 않는다.
- 합성의 정답 위치를 실제 수식의 분할 정답인 것처럼 사용하지 않는다. 실제 자동 분할을 거친 입력을 본 학습의 기준으로 삼는다.
- 난수 시드 42와 실행 환경·라이브러리 버전·데이터 해시를 기록한다. 정확한 수식 내용 조회나 시험 정답을 활용한 후처리를 사용하지 않는다.

주 검증 선택 점수 S = 0.7×사진 검증 전체 일치율 + 0.3×MathWriting 검증 전체 일치율.
동률이면 정규화 토큰 편집 거리가 낮은 체크포인트를 선택한다. 사진 검증이 없으면 이 점수가 정의되지 않으며 임시 디지털 개발 실행과 최종 통합 실행을 구분한다.

## 9. 최종 시험은 고정된 한 모델로 실행

- 데이터·전처리·병합 기준·모델 구조·토큰 사전·체크포인트·디코딩을 고정하고 선택 기록을 저장한다.
- 새 MathWriting 시험 400장과 새 사진 120장을 같은 이미지 전용 추론 경로로 처리한다.
- 사진이 주 결과이며 두 자료의 정확도를 합쳐 하나의 사진 성능으로 제시하지 않는다.
- greedy decoding을 사용하고 EOS 또는 최대 64토큰에서 종료한다. 정답 길이를 사용하지 않는다.
- 주 결과를 본 뒤 모델을 다시 고치면 기존 시험을 개발 자료로 전환하고 새 시험을 확보한다.

## 10. 측정과 오류 분석도 같은 실험 안에 포함

주 지표: 전체 수식 일치율.
보조 지표: 총 토큰 편집 거리/총 정답 토큰 수, 구조별 일치율, 문법/종료 실패율, 이미지당 처리 시간.

- 공백·명령어 동의어와 유효한 구문 트리의 직렬화 차이를 정규화한다. 연산 순서·기호·대소문자·소수 표기는 보존한다. 계산이나 교환법칙으로 동치 판정을 하지 않고, 잘못 닫힌 괄호를 복구하지 않는다. 원시 토큰열 일치율도 함께 보고한다. 구체적인 규칙은 20절에 고정한다.
- 사진의 정상 자동 입력 결과가 주 결과다.
- 같은 사진에 정답 기호 영역을 제공한 결과, 정답 기호도 제공한 결과를 추가 계산하여 분할·분류·구조의 오류를 진단한다. 이 행들을 실제 인식 정확도나 별도 완료 실험으로 부르지 않는다.
- 영역 IoU≥0.5의 최대 일대일 대응으로 분할 정밀도·재현율·F1을 계산한다.
- 정답 기호 crop에서 CNN 정확도·Macro F1·혼동 행렬을 계산한다. 특히 1/l, 0/O, x/×를 기록한다.
- 오류는 과분할·오병합·누락·잡음·기호 분류·분수 관계·첨자 관계·문법·종료로 중복 표시할 수 있게 한다.
- 정답 기호 one-hot을 주는 진단은 입력 분포가 바뀌므로 엄밀한 성능 상한이 아니다. 단계별 차이를 단순 합산하지 않는다.
- 수식 내용 ID 단위로 재표집하여 전체 정확도의 95% bootstrap 구간을 구한다. 분수의 두 표기를 함께 재표집한다. 동일 세 필자에 조건부인 평가 범위를 명시한다.

## 11. 분수는 한 모델의 입력 표기 조건으로 비교

학습에 두 표기를 균형 있게 포함한다. 최종 모델은 같고 시험 사진 30쌍만 표기가 다르다. 분자·분모 내용, 정답 LaTeX, 촬영 조건, 필자를 짝맞춘다.

기록: 둘 다 성공, 상하만 성공, 슬래시만 성공, 둘 다 실패. Δ=슬래시 일치율−상하 일치율과 쌍 단위 bootstrap 95% 구간을 보고한다.

- 슬래시 정확도≥80%, Δ≥10%p, 차이 구간 하한>0이면 슬래시 우선 입력 안내를 제안한다.
- 그 외에는 실제 측정치를 제시한다. 유의한 차이를 못 찾은 것을 두 표기의 동등성 입증으로 해석하지 않는다.
- 두 표기가 모두 낮으면 결과 확인·수정이 필요한 도구로 설명한다.
- 이 설계가 측정하는 것은 같은 혼합 학습 모델의 표기별 인식 성능이다. 표기별 독립 모델의 학습 난이도 차이에 대한 주장은 하지 않는다.

## 12. 시간 측정·결과 표시·저장

- 같은 CPU 환경에서 이미지 파일 읽기부터 LaTeX 생성까지 측정한다. 모델은 한 번 로드한다.
- 워밍업 10장 후 사진 시험 120장을 3회 측정한다. 중앙값, 95백분위, 전처리/분할/CNN/LSTM 시간을 기록한다.
- 한 사진에서 나온 기호는 묶어서 CNN에 넣는다. CPU 스레드 수, 이미지 크기, 장치, 버전을 기록한다.
- 모델 로딩과 화면 렌더링은 별도 시간으로 기록한다.
- 화면에서 원본, 인식 수식, 원시 LaTeX, 복사 버튼을 제공한다. 출력 문법이 맞는 것과 내용이 맞는 것을 구분한다.
- 통합 체크포인트에 CNN·인코더·디코더 가중치, 기호/토큰 사전, 전처리/분할 설정, 데이터 해시, 시드, 검증 선택 근거를 함께 저장한다.

## 13. 완료 기준과 최종 산출물

아래가 모두 있어야 전체 실험을 완료로 기록한다.

1. 실제 수식 중심 학습 자료와 새 검증·시험 목록 및 중복 검사.
2. 실제 촬영 240장과 검수한 정답. 사진이 없으면 데이터 대기로 기록한다.
3. 이미지 하나만 받아 실행되는 전체 파이프라인과 저장/불러오기 검증.
4. 최종 고정 모델의 새 사진·MathWriting 시험 결과.
5. 분수 30쌍 비교, 단계별 오류 진단, 처리 시간.
6. 결과 표시·복사, 재현 설정, 실제 실행 로그, 최종 보고서.

도구의 초기 실용성 목표는 사진 전체 일치율 80% 이상, CPU 95백분위 1초 이하다. 미달해도 자료·절차·결과가 완전하면 실험은 완료하며, 도구의 한계를 결과에 명시한다.

최종 결과표:

| 하나의 최종 모델 | 전체 일치율 | 토큰 편집 거리 | 사진 수/내용 수 | CPU p50/p95 |
|---|---:|---:|---:|---:|
| 새 수식 사진 | 측정 | 측정 | 120장/90내용 | 측정 |
| 새 MathWriting 실제 수식 | 측정 | 측정 | 확보 수량 명시 | 별도 측정 |

부록은 같은 시험의 구조별 결과·분수 쌍 결과·진단 결과·오류 사례로 구성한다. CNN 수치나 합성 수식 수치만으로 전체 실험의 성공을 선언하지 않는다.

구현 시 단일 실행 진입점이 준비→검사→학습→검증 선택→고정→시험→오류 분석→보고서를 연속 수행하도록 구성한다. 중단 시 전체 실험의 상태를 저장하고 이어서 실행한다. 현재는 설계 문서와 설정만 있으며 새 70종 실험은 아직 실행하지 않았다.

## 14. 원본 선정과 데이터 확정 절차

MathWriting의 실제 수식은 train 4,000 / valid 400 / test 400을 목표로 한다. 각각 기본·위첨자·아래첨자·분수를 1,000/1,000/1,000/1,000 또는 100/100/100/100으로 배분한다.

주 유형은 분수 포함 → fraction, 분수 없이 ^ 포함 → sup, 두 조건 없이 _ 포함 → sub, 나머지 → basic 순으로 배정한다. 별도로 has_sup/has_sub/has_fraction 태그를 모두 기록한다. 혼합 구조는 주 유형에 한 번만 세고, 여러 오류 태그로 진단한다.

필터는 다음 순서로 고정한다.

1. 사람이 쓴 원본인지, 공식 분할이 무엇인지 확인한다.
2. normalizedLabel을 토큰화하고 공백·기본 명령어 동의어·글꼴 장식을 정규화한다.
3. 70종 기호와 구조 토큰으로 파싱 가능한지 확인한다.
4. 보이는 기호가 3~16개, 출력 내용이 63토큰 이하(EOS 포함 64토큰 이하)인지 확인한다. 숫자는 자리별, 분수선은 한 개로 센다.
5. 한 수식의 분수는 최대 하나, 첨자 내부에 첨자가 없고 첨자 내용은 영문 한 글자 또는 숫자 1~2자리인지 확인한다. 분자·분모의 한 단계 첨자는 허용한다.
6. 과거 시험·UI 예시에 사용한 MathWriting ink_id를 제거한다. 시험 후보 부족 시 목표 수량 변경을 사전에 기록한다.
7. 정규화된 수식 트리와 원본/획/이미지 해시로 중복을 검사한다.
8. 같은 유형의 후보를 SHA256(source_id + '|42|' + split) 값으로 정렬하여 순서대로 선정한다. 이미지가 어려워 보인다는 이유로 재선정하지 않는다.
9. 검증·시험과 같은 내용의 학습 수식을 제거한다. 부족한 학습 수식은 남은 공식 train 후보에서 다시 선정한다. 공식 test를 학습으로 옮기지 않는다.
10. 400개 시험 내용, 400개 검증 내용과 capture_plan의 검증/시험 내용은 학습 내용과 겹치지 않도록 검사한다. 두 시험 자료 사이 내용 중복도 제거하여 수식 단위 통계를 명확히 한다.

필터별 입력 수·제외 수·제외 사유, 목표 대비 실제 수량, 이전 사용 ID 제외 수를 data_audit.json에 저장한다. 정답 검수·범위 필터를 위해 시험 라벨을 준비하는 것과, 시험 예측을 보고 모델을 선택하는 것은 구분한다. 전자는 사전에 수행하고 후자는 허용하지 않는다.

## 15. 촬영 문항표와 촬영 조건

CAPTURE_SHEET.md는 필자 A/B/C별로 정확한 파일명, 수식, 표기를 지정한다. capture_plan.json에는 240개 문항과 계획 정답·수식 ID·분수 쌍 ID가 있다.

문항표 자체에서 검증한 사항:

- 학습 72장/54내용, 검증 48장/36내용, 시험 120장/90내용.
- 각 집합에 70종 기호가 모두 등장한다. 실제 사진에서의 등장 여부는 수집 후 다시 확인한다.
- 집합 간 동일 수식 내용은 없다.
- 분수 두 표기는 파싱한 수식 트리가 동일하다.
- 각 프롬프트의 보이는 기호 수는 3~16개다.

촬영은 다음 조건으로 진행한다.

- A/B/C와 세 필자의 대응을 한 번 정하여 고정한다.
- 흰 무지 종이, 검은 펜 0.5~0.7mm, 평소 필체를 사용한다.
- 글자 높이 약 8~15mm를 기준으로 하되 글자를 정해진 칸에 억지로 맞추지 않는다.
- 휴대폰 주 카메라 1배, 약 25~40cm 거리, 종이에 거의 수직(약 10도 이내), 자동 초점 상태에서 촬영한다. 필터·인물 모드는 사용하지 않는다.
- 수식 주위 여백을 남긴다. 인쇄된 프롬프트·문항 번호·LaTeX 정답은 인식 ROI에 포함하지 않는다.
- 같은 분수 쌍은 같은 필자·펜·카메라·조명에서 연속 촬영한다. 상하/슬래시 작성 순서는 쌍마다 번갈아 배정했다.
- 서로 다른 split의 문항을 같은 종이에 섞지 않는다. 변형본이나 재촬영본은 원본과 같은 split에 둔다.
- 주 시험은 정상적으로 읽을 수 있는 사진을 대상으로 한다. 잘림·초점 실패는 모델 예측 전 수집 검수에서 재촬영하고 원인을 기록한다.
- 프롬프트와 다르게 썼으면 사진에 맞는 정답을 확인한다. 분수 쌍의 내용이 달라졌다면 예측 전에 다시 작성하여 짝을 맞춘다.
- 원본 JPEG와 ROI/전처리 기록을 보관한다. ROI 선택은 수식 하나 전체에 대해서만 허용하며, 평가 조건과 사람이 선택한 시간의 제외 여부를 보고한다.

현재 capture_plan의 image_path와 glyphs는 null이고 collection_status는 not_collected다. 문항 생성 수를 수집 완료 수로 세지 않는다.

## 16. 정답 표시와 검수 규칙

사진마다 다음을 기록한다.

- 원본 사진 경로, 수식 전체 ROI, 수정하지 않은 원본 해시.
- 실제 사진에 쓰인 LaTeX, 정규화 토큰열, 주 유형·보조 구조 태그.
- 각 기호의 class_id, 원본 이미지 좌표계의 (xmin,ymin,xmax,ymax), component/획 마스크가 있으면 그 경로.
- 좌표는 왼쪽·위 포함, 오른쪽·아래 미포함으로 통일한다.
- 한 기호의 모든 획을 포함한다. i/j 점과 몸체, = 두 획은 같은 기호다. 위·아래첨자 숫자도 각각 별도 기호다.
- 영역에 불필요한 이웃 획이 포함되었는지 검수한다. 진단용 GT crop에서 이웃 기호가 겹치는 경우 이를 표시하고 마스크 crop과 bbox crop을 구분한다.
- 작성자와 다른 사람이 라벨·영역을 검수하고 annotation_status=reviewed로 표시한다.

모든 사진은 예측 전에 검수한다. 검수 이후 발생한 모델 오인식·빈 출력은 데이터 불량을 이유로 평가에서 제거하지 않는다.

CNN 보조 풀은 MathWriting symbols/CROHME train에서 클래스 매핑을 검토한 뒤 생성한다. 분수선만 '-' 시각 클래스로 합치고, O/0, l/1, x/×는 유지한다. 클래스별 서로 다른 원본 50개가 부족하면 추가 작성 목록을 출력하여 채운다. 이 추가 기호는 학습 전용이며 사진 240장과 별도 원본 수로 보고한다.

## 17. 전처리·분할의 실행 명세

전체 ROI는 같은 함수로 처리하며 다음 중간 결과를 저장할 수 있어야 한다.

1. EXIF 방향을 반영하고 투명 영역은 흰색으로 합성한다. 초기 긴 변이 1600px를 넘으면 비율 유지 축소하고 좌표 변환을 기록한다.
2. 흑백 이미지 I에서 가우시안 배경 B를 구한다. 초기 sigma=max(8,0.05×min(너비,높이)), Icorr=clip(255×I/(B+epsilon),0,255), epsilon=1을 사용한다.
3. Otsu 역이진화로 필기=1, 배경=0 마스크를 만든다.
4. 예비 연결 성분에서 점·얇은 선을 제외한 높이의 70백분위를 H0로 잡는다. 일반 글자 높이가 약 48px가 되도록 비율 유지 크기 조정을 하되 전체 너비≤1024px, 높이≤512px를 지킨다.
5. 이진화·8방향 연결 성분을 다시 계산하고 좌표 변환을 기록한다.
6. =, i/j 병합 후보를 계산한다. 후보 점수가 높은 순으로 처리하고 조각의 중복 소속을 금지한다.
7. 병합 이후 면적<max(2,0.002H²)이면서 다른 유효 성분과의 거리가 H보다 큰 고립 성분을 잡음 후보로 제거한다. 가까운 소수점은 크기만으로 지우지 않는다.
8. 각 그룹의 실제 마스크에 해당하는 획만 남겨 기호 crop을 만든다. 28×28 안에 맞춰 32×32에 가운데 배치하고, 필기 1·배경 0의 float32로 변환한다.

i/j 후보는 점의 너비·높이≤0.25H, 몸체 높이≥0.5H, 몸체 너비≤0.6H, 점 면적≤몸체 면적×0.2인 경우를 초기 기준으로 한다. x 중심 차이≤0.25H, 점이 몸체보다 위, 세로 간격≤0.4H 조건을 함께 적용한다. 한 점에 여러 몸체가 경쟁하면 거리 점수가 가장 좋은 하나만 고려하고 모호한 경우 미병합으로 남긴다.

붙은 글자·끊어진 획·기울어진 등호 등 이 규칙이 해결하지 못한 사례도 그대로 시험에 포함한다. 후보가 0개 또는 64개 초과면 전체 인식 실패로 기록한다. 실패를 피하려고 임의의 64개만 잘라 쓰지 않는다.

보정/이진화/임계값 변경은 검증 단계에서만 수행하며 설정 버전을 남긴다. 최종 시험에서는 자동 전처리와 좌표 변환을 동일하게 적용한다.

## 18. 텐서·디코딩·기울기 흐름 명세

수식 배치 B=10, 전체 배치의 기호 수 M, 수식별 기호 수 N_i, 최대 기호 수 Nmax라 하면:

| 텐서 | 모양 |
|---|---|
| 기호 이미지 | M×1×32×32 |
| CNN logits / probabilities | M×70 |
| 수식별 입력 | N_i×78 |
| 패딩된 입력 | B×Nmax×78 |
| 인코더 투영 | B×Nmax×64 |
| 양방향 최종 h/c | 각각 2×B×128 |
| 디코더 초기 h/c | 각각 1×B×256 |
| 디코더 출력 점수 | B×T×79 |

기하 8개는 7절 순서로 연결한다. 첫 기호의 이전 기호 대비 차이는 (0,0), Hchar는 분할에서 추정한 H이며 최소 1로 둔다. 네 개의 상대 기하값을 [-4,4]로 제한한다. 패딩 길이는 pack/mask로 제외하고 정답 수식 길이를 인코더에 주지 않는다.

고정 출력 사전은 그림 기호의 LaTeX 표현 70개 + 구조 토큰 5개(\frac,^,_,{,}) + 특수 토큰 4개로 79개다. 데이터 확정 시 중복·누락을 검사한다.

- 학습 디코더 입력: BOS + 정답 토큰. 목표: 정답 토큰 + EOS.
- 패딩 위치는 손실에서 제외한다.
- 평가 입력은 BOS로 시작하고 이전 예측만 사용한다. BOS/PAD/UNK는 출력 후보에서 마스킹한다.
- EOS가 나오면 종료한다. 64토큰까지 EOS가 없으면 종료 실패다.
- Beam search·정답 길이·공식 정답 조회·자동 괄호 복구를 사용하지 않는다.
- 정규 추론 API는 이미지와 선택적인 전체 ROI만 받는다. 정답 라벨과 영역은 평가 함수에서 예측이 끝난 뒤 결합한다.

주 손실 Lseq는 수식별 유효 토큰 교차 엔트로피 평균을 구한 후 B개 수식에 대해 평균한다. Lsym은 별도 정답 기호 64개의 교차 엔트로피 평균이다. L=Lseq+0.3Lsym.

CNN 초기화 이후 첫 3개 본 에포크는 CNN을 고정하고 Lseq로 인코더·디코더만 갱신한다. 이후 CNN probabilities를 detach하거나 numpy로 바꾸지 않고 연결하여 Lseq의 기울기도 CNN에 전달한다. 이산 분할 규칙에는 역전파하지 않는다. 같은 CNN에 Lsym도 계산하여 두 손실을 한 번의 최적화에 합친다.

초기 구조의 예상 파라미터 수는 약 70만개다. 구현 후 실제 수를 기록한다. 기본 수치는 float32이고 RTX 3050 Ti 4GB급 환경에서 동작하도록 수식 배치 10을 사용한다. 메모리가 부족하면 유효 배치 10을 유지한 gradient accumulation으로 처리하고 실행 기록에 남긴다.

## 19. 한 에포크와 검증 주기의 정확한 정의

- 시드: Python/NumPy/PyTorch/CUDA에 42, 데이터 선정·증강·추출 시드도 기록한다.
- CNN 초기화: 각 클래스에서 에포크당 100번씩 균형 추출하여 총 7,000기호를 본다. 배치 64, 마지막 배치는 작게 허용한다. 같은 원본의 반복 추출과 증강을 새 원본으로 세지 않는다. 총 10에포크다.
- 본 학습 한 에포크: 600 step. step마다 실제 MathWriting 6장, 합성 3장, 학습 사진 1장과 보조 기호 64개를 추출한다.
- 따라서 에포크당 수식 추출은 6,000번이며 원본 6,000개를 모두 한 번씩 본다는 뜻은 아니다. 출처별 3,600/1,800/600회 추출이다.
- 본 학습에서는 각 출처의 주 유형 4개를 균형 있게 추출한다. 합성/사진의 분수는 두 표기 1:1로 추출한다. MathWriting 분수 표기는 실제 분포를 기록한다.
- 학습마다 약한 증강을 새로 적용하고 분할도 다시 계산한다. 검증은 증강 없이 자동 분할을 사용한다.
- 매 에포크 끝에 MathWriting 검증 400장과 사진 검증 48장 모두를 자유 생성으로 평가한다.
- S=0.7EMphoto+0.3EMmathwriting. 동률이면 0.7NERphoto+0.3NERmathwriting가 작은 것을 선택한다. 또 동률이면 더 이른 에포크를 선택한다.
- 15에포크 이전에는 조기 종료하지 않는다. 15에포크 이후 최고 선택 순위가 8에포크 연속 개선되지 않으면 종료한다. 최대 60에포크에는 처음 3개 적응 에포크가 포함된다.
- 저장 항목: best 통합 가중치, last 가중치, optimizer 상태, epoch/step, RNG 상태, 클래스/토큰 사전, 데이터/설정 해시, 검증 선택 순위.
- 검증 중에는 eval 모드와 inference/no_grad를 사용한다. 시험은 본 학습 루프에서 실행하지 않는다.
- 재개 실행은 같은 데이터/설정 해시인지 확인하고 optimizer와 RNG까지 복원한다. 독립된 새 실험으로 분리하지 않는다.

사진 학습/검증이 없으면 이 출처 비율과 선택 점수를 충족할 수 없다. 그 상태는 같은 전체 실험의 데이터 준비 대기로 기록하고, 사진 없는 임시 학습을 최종 완료로 대체하지 않는다.

## 20. 수식 정답 정규화와 평가 계산

평가 전에 동일한 정규화기를 학습 정답·예측에 적용한다.

1. 공백·미리 지정한 명령어 동의어를 정리한다.
2. 유효한 수식만 구문 트리로 파싱한다. 숫자 문자열, 연산자, 연산 순서, 변수 대소문자를 보존한다.
3. 슬래시 나눗셈과 \frac를 동일한 나눗셈 노드로 처리한다. 불필요한 표기용 그룹 차이만 통일한다.
4. 같은 트리의 직렬화를 정규화 결과로 사용한다. x^2와 x^{2}는 같은 구조가 될 수 있지만 x+l과 x+1은 다르다. x+y와 y+x를 합치거나 수식을 계산·약분하지 않는다. 1.0과 1.00의 원래 숫자 표기도 유지한다.
5. 파싱 실패를 괄호 삽입 등으로 복구하지 않는다. 실패는 전체 일치율에서 오답이고 문법 오류로 기록한다.

유효한 EOS 종료와 문법을 모두 만족하고 정규화 후 전체 수식이 같은 이미지 수 / 전체 시험 이미지 수를 주 전체 일치율로 정의한다. EOS 미출력·빈 입력·처리 한도 초과는 내용이 우연히 맞더라도 실패다.
원시 토큰열 완전 일치율도 함께 기록하여 정규화 효과를 공개한다.

직렬화기는 우선순위에 맞는 최소 괄호, \frac{분자}{분모}, base^{첨자}, base_{첨자} 형식을 사용한다. 프로젝트의 기존 canonical()처럼 곱셈/나눗셈 항을 재배열하는 정규화는 이 지표에 그대로 사용하지 않는다. normalize(parse())의 구체적인 함수 버전과 해시를 시험 전에 고정한다.

정규화 토큰 편집 거리는 유효 예측에는 정규화 직렬화 토큰을, 무효 예측에는 공백/명령어 정리만 한 원시 예측 토큰을 사용하고, 데이터셋 전체 편집 거리 합/정답 토큰 수 합으로 계산한다. 편집 거리는 삽입·삭제·치환 비용 1의 Levenshtein 거리다. 유효/무효 예측의 평가 경로를 기록한다.

사진 시험의 신뢰구간은 필자×내용 유형으로 층화하고 수식 내용 ID를 단위로 1,000회 재표집한다. 분수 한 내용의 두 표기는 함께 뽑는다. 각 반복에서 이미지 수 120, 분수 쌍 30을 유지한다. 2.5/97.5백분위를 보고하며, 세 필자를 대상으로 한 조건부 평가임을 표시한다.

분수 비교에서는 30쌍에 대해 Δ=(슬래시만 성공 수−상하만 성공 수)/30을 계산한다. 예측 차이를 보기 전에 표기 순서와 쌍을 확정한다. CI 하한>0, 점 추정 차이≥10%p, 슬래시 정확도≥80% 조건이 모두 충족될 때만 슬래시 우선 안내를 제안한다.

## 21. 같은 시험에서 수행할 진단

주 결과는 이미지 전용 자동 추론이다. 그 후 같은 모델/이미지에서 진단 조건을 적용한다.

| 입력 조건 | 목적 |
|---|---|
| 자동 분할 + CNN 확률 | 실제 전체 결과 |
| 정답 영역/마스크 + 같은 CNN | 영역 오류의 영향 진단 |
| 정답 영역 + 기호 one-hot | 구조 생성의 잔여 오류 진단 |

후보 순서·위치 계산·디코더는 공유한다. 진단에는 input_mode를 기록하여 주 결과와 혼동하지 않게 한다. 진단 결과를 보고 최종 시험용 모델을 다시 선택하지 않는다.

추가 기록:

- Box IoU≥0.5 일대일 대응은 유효 대응 수를 먼저 최대화하고, 동률에서 IoU 합이 큰 것을 선택한다. TP/FP/FN과 precision/recall/F1을 저장한다.
- 기호 정확도·Macro F1은 정답 crop에서 측정하고, 클래스별 원본 수와 혼동 행렬을 함께 저장한다. 없는 클래스를 높은 정확도로 보충하지 않는다.
- 1/l, 0/O, x/×의 양방향 오분류 수와 각 정답 표본 수를 별도 표로 낸다.
- 전체 오류 사진은 과분할·병합·누락·잡음·분류·분수·첨자·문법·종료 중 여러 원인을 표시할 수 있다.
- 판별 근거가 부족한 원인은 추측으로 단정하지 않고 미확정으로 남긴다.
- 사례 그림에는 원본, 예측 영역, 기호 후보 확률, 예측/정답 LaTeX를 함께 둔다.

## 22. 이미지 전용 실행과 사용자 화면의 검증

같은 recognize(image, roi=None) 함수가 UI·CLI·시험 평가에 사용되어야 한다. 함수는 정답과 문항표를 읽지 않는다.

반환값: status, latex, tokens, syntax_valid, segments, stage_times, checkpoint_id, protocol_hash.

- 빈 영역, 기호 후보 초과, EOS 미출력, 문법 오류는 상태로 반환하고 시험 분모에 포함한다.
- 화면에는 원본과 인식 수식·LaTeX를 표시하고 복사 버튼을 제공한다. 수식을 렌더링하지 못하면 원시 코드를 확인할 수 있게 한다.
- 사용자가 수정을 할 수 있어도 정확도는 수정 전 모델 출력으로 계산한다.
- 모델 저장 후 새 프로세스에서 불러온 결과, CLI 결과, 평가 결과가 동일한지 확인한다.
- 같은 이미지에 다른 정답 메타데이터를 붙여도 정상 recognize 출력이 바뀌지 않는지 확인한다.
- GT 영역 입력은 진단 함수의 명시적인 경로에서만 허용한다.

CPU 시간은 단일 스레드·한 사진 입력 기준으로 측정한다. 한 사진의 기호들은 묶어서 CNN에 입력한다. 워밍업 10장 후 실제 사진 120장×3회=360번을 측정하고 p50/p95와 단계 평균을 보고한다. 파일 읽기와 자동 전처리를 포함하고 모델 로딩·수동 ROI 선택·사용자 수정·화면 렌더링은 별도 항목으로 둔다. 같은 이미지의 반복 시간 측정을 서로 다른 시험 사례로 세지 않는다.

## 23. 단일 실행의 상태·산출물·중단 처리

구현할 진입점의 역할은 다음 연속 절차다. 아직 실행 프로그램 자체를 구현한 것은 아니다.

DESIGNED → DATA_PREPARING → DATA_LOCKED → TRAINING → VALIDATING → FROZEN → TESTING → REPORTING → COMPLETE.

데이터 준비에서는 누락 파일·검수 미완료·클래스 부족·교차 중복을 missing_data.json에 기록한다. 부족 자료를 합성 사진으로 꾸며 다음 단계로 넘어가지 않는다. 중단 시 같은 experiment_id로 저장된 상태에서 재개한다.

최종 한 묶음의 산출물:

| 파일 | 내용 |
|---|---|
| protocol.json / protocol_hash | 최종 설정과 버전 |
| manifest.jsonl / data_audit.json | 실제 원본·라벨·분할·중복 검사 |
| final_model.pt | 선택한 CNN·인코더·디코더와 사전/전처리 설정 |
| training_history.jsonl | 각 에포크 손실·검증 점수·선택 이력 |
| frozen_selection.json | 시험 전에 확정한 체크포인트와 선택 근거 |
| predictions.jsonl | 시험 전체 520장 목표의 수정 전 예측·실패 상태 |
| metrics.json | 사진/MathWriting별 전체 지표와 신뢰구간 |
| fraction_pairs.json | 30쌍 비교와 입력 안내 근거 |
| diagnostics.json | 같은 시험의 단계별 진단 |
| latency.json | 실제 사진 CPU 3회 시간 측정 |
| error_gallery.html / figures | 오인식 사례와 학습/결과 그림 |
| REPORT.md | 실제 실행 결과·한계·재현 방법 |

미수집 자료가 있으면 그 수량과 같은 전체 실험의 현재 상태를 보고한다. 70종 학습·최종 시험을 아직 하지 않은 시점의 수치는 계획값과 섞지 않는다.

## 25. 실제 실행에 따른 사전 수량 갱신 (2.1)

원본 전체를 검사하고 정규화/중복/지원 범위를 적용한 실측 선정 수량은 학습 3,872개, 검증 363개, 시험 317개다. 기존 목표 4,000/400/400은 목표로 남기고 실측 전부를 사용하도록 본학습 전에 갱신했다. 부족분을 복제하지 않았다. 학습 보조 합성 2,000장과 기호 원본 50,482개를 준비했다. 현재 사진은 0장이며 본학습과 시험 예측은 시작하지 않았다. 실제 진행 상태·구현 미완료 항목은 RUN_STATUS.md와 state.json을 우선 확인한다.
